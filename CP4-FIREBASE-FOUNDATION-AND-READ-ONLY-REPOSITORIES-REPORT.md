## 3. Firebase configuration and environment-variable contract

**Project:** `sledge-classroom` (unchanged; no new project created).

**SDK:** Firebase modular SDK (`firebase` v13.2.0) — `firebase/app`, `firebase/firestore`, `firebase/database`. No Admin SDK, no service-account credentials.

**Environment variables** (Vite-prefixed, exposed to client; documented in `modern/.env.example`):

| Variable | Source | Notes |
|----------|--------|-------|
| `VITE_FIREBASE_API_KEY` | Firebase project settings | Public web API key (identifier, not secret) |
| `VITE_FIREBASE_AUTH_DOMAIN` | `sledge-classroom.firebaseapp.com` | |
| `VITE_FIREBASE_PROJECT_ID` | `sledge-classroom` | Preserved exactly |
| `VITE_FIREBASE_DATABASE_URL` | `https://sledge-classroom-default-rtdb.firebaseio.com` | RTDB |
| `VITE_FIREBASE_STORAGE_BUCKET` | `sledge-classroom.firebasestorage.app` | |
| `VITE_FIREBASE_MESSAGING_SENDER_ID` | project settings | |
| `VITE_FIREBASE_APP_ID` | project settings | |

**Security rules:** `firestore.rules` (public read on `courses/...` and `events/...`, owner write) and `database.rules.json` (`nowPlaying/current` public read) are **unchanged**. Firebase config is public client configuration; security is enforced by rules, not by hiding values.

**`.env.local` / `.env.*.local`** are gitignored and must never be committed. `.env.example` contains placeholder values only — no secrets.

**Initialization behavior:** Firebase is initialized only when all required `VITE_FIREBASE_*` vars are present. Duplicate init is guarded via `getApps()`. When unconfigured, exported services are `null` and `firebaseConfigured` is `false`. Repositories surface a `FirebaseNotConfiguredError` when invoked without configuration — no silent fallback to invented data.

## 4. Repository interfaces and verified data models

All repository methods return `RepositoryResult<T>` (discriminated by `data`/`error` presence):

```ts
interface RepositoryError { code: string; message: string; }
interface RepositoryResult<T> { data: T | null; error: RepositoryError | null; }
```

### 4.1 CourseRepository (`src/services/repositories/courseRepository.ts`)

**Legacy contract:** `courses/{courseId}/{category}/{fileId}` — public read.

**Method:** `listResources(courseId, category): Promise<RepositoryResult<ResourceFile[]>>`

**`ResourceFile` model (legacy field semantics preserved):**
`id, courseId, category, name, url, previewURL, downloadURL, type, description, date, createdAt`

`courseId`, `category`, and `type` are validated against the legacy allowed enums; invalid values fall back to safe defaults (`stats`, `lectures`, `link`) rather than crashing. Missing/non-string fields default to `''`; `createdAt` defaults to `null`.

**Google Drive URLs:** Stored `url`/`previewURL`/`downloadURL` are passed through unchanged on read. URL normalization (Drive ID extraction, Dropbox `dl=0`→`dl=1`, scheme correction) is a **write-time** concern owned by `confirmUpload()` (deferred to a later checkpoint); no read-time normalization is invented.

### 4.2 EventRepository (`src/services/repositories/eventRepository.ts`)

**Legacy contract:** `events/{eventId}` — public read.

**Method:** `listEvents(): Promise<RepositoryResult<Event[]>>`

**`Event` model:** `id, title, date, time, type, courseId, groups, description, createdAt` (legacy semantics preserved).

### 4.3 NowPlayingRepository (`src/services/repositories/nowPlayingRepository.ts`)

**Legacy contract:** RTDB `nowPlaying/current` — public read (`.read: true`), write requires auth.

**Methods:**
- `getNowPlaying(): Promise<RepositoryResult<NowPlaying | null>>` — one-time read via `get()`
- `subscribeNowPlaying(onChange): () => void` — real-time subscription via `onValue`, returns unsubscribe

**`NowPlaying` model:** `title, artist, artwork?, ytLink?, updatedAt` — returns `null` for absent/null/non-object or title-less records.

## 6. Tests and exact results

**Framework:** vitest v5.1.0 (Node environment), 3 test files under `modern/test/repositories/`.

**Approach:** Firebase SDK modules (`firebase/firestore`, `firebase/database`) are mocked via `vi.mock` inline factories; no real Firebase SDK initialization or network occurs in tests. Repositories are constructed with `null` (unconfigured) or `{}` mock service objects.

**Coverage:**
- `mapResourceFile` / `mapEvent` / `mapNowPlaying`: complete mapping, missing fields, malformed enums, non-string fields, null/absent snapshots, non-object values
- Repository with `null` service: `firebase-not-configured` error, no SDK call attempted
- Repository with mocked service: successful mapping, empty collections, error propagation (`firestore-read-failed`, `rtdb-read-failed`)

## 8. Limitations and unresolved questions

- Authentication, admin guards, owner-only mutations, upload/edit/delete workflows are intentionally **not** implemented (read-only boundary). `confirmUpload()` and the transactional metadata-edit contract are documented for later checkpoints.
- Firebase is not initialized in environments lacking the `VITE_FIREBASE_*` vars; repositories throw `FirebaseNotConfiguredError` when invoked. Local development requires copying `.env.example` to `.env`/`.env.local` with real (public) project values.
- The `@/` path alias is configured in `vite.config.ts`, `tsconfig.app.json`, and `vitest.config.ts`.
- No production deployment was performed; the modern app is not yet wired to Firebase Hosting (Hosting `public` remains `.`).
